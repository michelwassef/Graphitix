Severity rubric
---------------
P1 / High
  Breaks a Graphitix architectural invariant (tab ownership/isolation, reopen parity, canonical geometry/state),
  breaks a broadly shared interaction, loses/restores the wrong owner state, or blocks an important workflow.

P2 / Medium
  Localized but user-visible correctness, interaction, or performance defect without demonstrated data loss or
  broad cross-component corruption.

P3 / Low
  Cosmetic/minor defect with no meaningful correctness or workflow impact. None of the persistent real failures
  in this run fit P3.

Important triage rule used here
-------------------------------
A test was marked stale only where the current intended contract could be established independently from the
failing assertion (current production code/architecture, current curated fixtures, or a false-positive assertion).
A removed helper/function name alone was NOT considered sufficient evidence of staleness. In particular, the Box
reserve source-contract tests remain real failures because independent browser tests reproduce the geometry defect.

Severity: P1 / High
Root-cause confidence: Very high; both browser and direct shared-axis traces now isolate the two independent defects.
Status: wheel-burst path VERIFIED PASS on Windows Chromium; manual fallback-offset fix applied, pending Windows Jest rerun.

R09 — Large Data-values Heatmap cancel/retry could reuse a stale committed model
Severity: P1 / High
Root-cause confidence: Very high; worker completion plus the cancelled render checkpoint isolate the stale-cache transition.
Status: FIX APPLIED 2026-08-15; authoritative Chromium reruns no longer show the former 180 s stall. The 2026-08-16 settled-state reruns now reach and validate the correct committed `values` model at 7,358 x 3. Two downstream assertions inherited from the original v25 test were stale and had previously been unreachable: the imported two-condition matrix intentionally changes the data-aware settings signature, and column-label export needs an aspect-correction matrix only when the live column labels actually carry one. The final full-spec rerun remains pending because later resize/export assertions have not yet executed to completion.
Tests:
  PW08 e2e/heatmap.large-data-values.responsiveness.spec.js
      large Data-values heatmap stays responsive and completes exact clustering
Finding:
  Exact clustering was not hanging: the 7,358-row worker had already completed. Before the candidate render model was
  committed, the draw path wrote the new data/settings signatures into the committed render runtime. Cancelling at the
  delayed render checkpoint therefore left the old WDBC `lastRenderModel` paired with the new large-data signatures.
  Retry saw matching signatures, accepted that stale model as a cache hit, hid the overlay, and never published the
  7,358-row graph.
Fix:
  Request signatures remain on the owner-scoped async draw token until `renderModelWithView()` commits the matching
  model. Model-derived value-scale state is likewise no longer published before commit, and every committed-model clear
  now clears its signature pair through one shared helper. The E2E captures committed model/signature metadata before
  import, after worker completion, after cancellation, and after retry: the first three must remain identical, while the
  successful retry must atomically advance to the 7,358 x 3 model and new data/settings signatures. The 2026-08-16 Windows reruns showed both that Retry can settle before Playwright observes an intermediate `data-job-status=running` and that the imported two-condition matrix legitimately changes the data-aware `showValues` default relative to the 40-condition WDBC example.
