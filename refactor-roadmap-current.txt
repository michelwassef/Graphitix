======================================================================
1. NON-NEGOTIABLE ARCHITECTURE
======================================================================

1.1 Source of truth
-------------------
Persisted payload is canonical only while loading, importing, duplicating,
reopening, or recovering a file.

After hydration, the owning component session is canonical while the app is
live.

DOM controls, SVG/canvas output, HOT/AG Grid instances, DataViews managers,
notes widgets, active refs, and projection bridges are projections of the
owning session. They are not durable state.

Required flow:

  saved/imported/recovery payload
      -> hydrate owning component session
      -> live session is canonical
      -> project session to DOM/render roots
      -> DOM events resolve owner tab/session
      -> DOM events patch owner session immediately
      -> session updates payload/runtime snapshot
      -> reopen/recovery hydrates a new session from payload

1.2 Tab ownership
-----------------
Every workspace tab owns exactly one component session for its component type.
Durable tab-affecting state must live in the owner session or in an owner-keyed
registry documented in code.

Allowed module globals:
  - immutable constants;
  - setup/listener guards with no tab-varying state;
  - caches keyed by every tab-varying input;
  - transient visible-DOM projection bridges named `projected*Session`;
  - compatibility bridges with explicit deletion criteria.

Forbidden module globals:
  - durable control registries;
  - module-level `active*Session` mirrors;
  - unowned DataViews/notes/HOT/AG managers;
  - cached render models not keyed by owner and data/settings signature;
  - pending async/draw state that can outlive the owner tab without owner token.

1.3 Activation and projection
-----------------------------
Same-component activation must:

  1. Resolve the workspace-active tab id.
  2. Resolve that tab's component session.
  3. Bind transient projection bridges from that session.
  4. Project session state into visible DOM controls/render roots.
  5. Allow DOM reads only when root/session/workspace owner all match.

Activation must never capture transient DOM from one tab into another tab's
session.

1.4 DOM events and mutations
----------------------------
DOM is projection only.

Active DOM events may read their event target, resolve the owner tab/session,
and patch that owner session. Inactive tabs must never read live DOM, active
refs, active HOT/AG managers, active DataViews managers, active layout objects,
loading overlays, or active visual mirrors.

Current closure rule:
  - durable mutations must not call `getActive*SessionForState()` directly;
  - explicit event/draw/tab-owner sessions are preferred;
  - `get*ProjectionSession()` is allowed only as a visible-DOM compatibility
    bridge for controls that still lack a direct event/session owner;
  - remaining `getActive*SessionForState()` references are projection reads,
    activation bridges, fallback resolution, or read-only helper paths.

1.5 Scheduling and async work
-----------------------------
Scheduled work must be tab-scoped and serializable.

Scheduled metadata may contain only plain owner metadata and plain options, for
example:

  { tabId, reason, flags, serializableOptions }

It must not contain DOM nodes, Events, sessions, refs, HOT/AG instances,
DataViews managers, component roots, scheduler functions, or circular objects.

Async/worker/timer callbacks must carry owner metadata and, when needed, a
session generation or operation token. On completion they must resolve the owner
session by tab id, verify freshness, patch that owner session, and project to DOM
only if that owner is currently active.

1.6 Render-cache restore
------------------------
Render cache is a visual optimization, not a source of truth.

`domControls.js` owns restore policy:
  - load payload;
  - apply layout;
  - attempt render-cache restore if cache exists and signatures match;
  - validate restored visual content;
  - keep/promote valid cache;
  - clear invalid cache and force normal live draw.

Components must not decide that a render cache is authoritative. Components must
not keep post-restore draw-suppression windows. After restore, user edits,
resize, color/style/data/options changes must behave like a never-closed graph
and must invalidate runtime/archive render cache through shared/session APIs.

1.7 Manager ownership
---------------------
DataViews, notes, HOT/AG, and auxiliary managers must be owner-session or
owner-registry based.

Use shared helpers where possible:
  - `Shared.componentLifecycle.resolveOwnedObjectTabId()`
  - `Shared.componentLifecycle.ownedObjectBelongsToSession()`
  - `Shared.componentLifecycle.markOwnedObject()`
  - `Shared.componentLifecycle.ensureOwnedDataViewsManager()`
  - `Shared.componentLifecycle.refreshOwnedDataViewsManagerFromHot()`
  - `Shared.componentLifecycle.ensureOwnedNotesControl()`

Component-local owner-marker code is allowed only when the component has a real
component-specific owner source not handled by the shared helper. Document why
and add a deletion note if it cannot be removed immediately.

======================================================================
5. TEST TRIAGE POLICY
======================================================================

Before changing code, answer:
  1. What final owner/session invariant does the test assert?
  2. Does the test wait for a settled owner state?
  3. Are session, payload, and DOM expected to agree at that point?
  4. Is the observed value a legitimate final state or an intermediate draw?
  5. Is there trace/video/state-snapshot evidence?

If the test checks final session/payload/DOM disagreement after a settled state,
assume the component is wrong until proven otherwise.

If the test samples during a documented intermediate draw, resize observer echo,
hydration phase, or async loading phase, repair the wait to observe the settled
owner contract. Do not weaken the final expected state.

======================================================================
6. DEFINITION OF DONE
======================================================================

The planned session-first refactor is done when:
  1. Every component has an owner-session contract.
  2. Payload hydration and live session ownership are clearly separated.
  3. DOM is projection only for durable state.
  4. Inactive tabs never read live DOM or active managers in tested owner paths.
  5. Scheduled work is owner-scoped and serializable.
  6. Async/worker/timer callbacks are owner-tokened and stale-safe in tested
     owner paths; Venn network async remains intentionally component-specific.
  7. DataViews/notes/HOT/AG managers are owner-session or owner-registry based.
  8. Compatibility active mirrors are deleted or explicitly documented as
     transient bridges with deletion criteria.
  9. Durable `getActive*SessionForState()` mutations have been replaced by
     explicit owner/projection-session paths.
 10. Routine E2E gates pass without excluding non-parked blockers.
 11. Archive reopen and crash recovery preserve full component state in tested
     owner paths.
 12. No critical console errors are emitted in owner/reopen gates.
 13. Known parked issues are present in `root/issues.txt` and are not silently
     hidden by weakened tests.

Current closure verdict:
  - Items 1-13 are satisfied for the planned refactor scope, assuming the user
    confirms the final gates pass.
  - The only known open item is the separately parked heavy mixed Box/Scatter
    render-cache retention issue.

Therefore the refactor should be considered: CLOSED FOR THE PLANNED SESSION-
