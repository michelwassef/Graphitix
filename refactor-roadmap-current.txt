Architecture-contract rewrite

======================================================================
0. WHY THIS ROADMAP WAS REWRITTEN
======================================================================

The previous roadmap contained many correct observations, but it was not
operationally strict enough. It mixed historical notes, partial fixes, component
status, and future work. That made the refactor drift toward local wrappers and
assertion-specific patches instead of converging on one architecture.

This file is now the source of truth for the refactor. Future code changes must
be judged against the contract below, not against whether a single local test can
be made to pass.

Current evidence from the latest Windows validation:
  - Scatter/PCA focused gate passed: 8/8.
  - Priority 0C gate passed: 9/10.
  - Heatmap/Surface/Venn batch passed: 5/7.
  - ROC graph-type, scheduled/manual redraw, and ROC DataViews gates are now green.
  - Venn UpSet/numeric/species reopen fidelity is green again.
  - Remaining active failures are concentrated in:
      * Histogram density distribution-selection projection after reopen/switch:
        payload/session can retain normal + lognormal while visible checkboxes
        project only normal.
      * Heatmap view/model synchronization when switching from correlation view
        back to values: the visible dropdown can say Data values while the cached
        render model remains correlation.
      * Venn GO/STRING async result ownership remains parked as a dedicated
        blocker, separate from Venn UpSet/numeric/species reopen fidelity.

Interpretation:
  The program is not failing because tab isolation is impossible. It is failing
  because several components still have more than one source of truth:
  module-level active mirrors, per-tab sessions, payload/runtime snapshots, and
  visible DOM controls. During same-component switching and file reopen, these
  can disagree. The correct refactor direction is therefore to remove ambiguity,
  not to add more guards around ambiguity.

======================================================================
1. NON-NEGOTIABLE TARGET ARCHITECTURE
======================================================================

1.1 Payload/session hierarchy
-----------------------------

Persisted payload is canonical only at file load, file reopen, import, duplicate,
or crash recovery. Its job is to hydrate the live tab session.

After hydration, the owning component session is canonical while the application
is live.

DOM controls, rendered SVG, rendered tables, DataViews DOM, active refs, and
active HOT/root/managers are never canonical. They are projections of the active
session and event sources that patch the session.

Required flow:

  saved payload / imported payload / recovery payload
      -> hydrate owning component session
      -> live session is canonical
      -> project active session to DOM
      -> DOM events patch owning session
      -> session updates payload/runtime snapshot
      -> reopen hydrates a new session from payload

1.2 Session ownership
---------------------

Every workspace tab owns exactly one component session for its component type.
Durable tab-affecting state must live in that session, for example:

  session.state
  session.results
  session.cache
  session.notes
  session.advisor
  session.managers
  session.runtime
  session.timers
  another explicitly documented session-owned bucket

Module globals may exist only for:
  - immutable constants;
  - static caches whose keys include all inputs that can vary by tab;
  - setup/listener guards that contain no tab state;
  - temporary active mirrors that are populated from the session during activation
    and never treated as durable state;
  - compatibility shims awaiting deletion, with an explicit deletion gate.

A component is not considered refactored while durable state can still be changed
only in module globals and later captured opportunistically.

1.3 Activation contract
-----------------------

Same-component activation must follow this order:

  1. Resolve the workspace-active tab id.
  2. Resolve the owning session for that tab.
  3. Bind the active mirrors from that session.
  4. Project the session into visible DOM controls/render roots.
  5. Only then allow DOM reads that are explicitly part of active-tab capture.

Activation must never capture transient DOM from one tab into another tab's
session. If the requested tab id, workspace-active tab id, root owner tab id, and
session owner tab id disagree, the component must skip DOM capture and use the
stored session/payload state instead of guessing.

1.4 DOM projection contract
---------------------------

The DOM is projection only.

Active DOM events may read the event target, resolve its owner tab/session, and
patch that owning session immediately.

Inactive tabs must never read live DOM, active refs, active HOT instances, active
DataViews managers, active layout objects, loading overlays, or active visual
state mirrors. Inactive tab payload/runtime snapshots must come from stored
session/payload state.

Visible controls must be refreshed from the active session whenever a tab is
activated, a file is reopened, or a stored runtime snapshot is applied. Visible
controls must not be used to reconstruct inactive session state.

1.5 Scheduling contract
-----------------------

Scheduled work must be tab-scoped.

Scheduled draw/update work may receive only serializable owner metadata and plain
options, such as:

  { tabId, reason, flags, plainOptions }

It must never receive or store DOM nodes, Event objects, sessions, refs, HOT
instances, managers, component roots, scheduler functions, or circular objects.

This rule prevents bugs like the ROC circular `cloneSimple()` failure where DOM
notes controls leaked into pending draw options.

1.6 Async/worker/timer contract
-------------------------------

Every async operation that can resolve after another tab becomes active must
carry owner metadata:

  tabId
  session token or generation number when appropriate
  operation type
  stale-result policy

On completion, it must:
  - resolve the owning session by tab id;
  - verify the session token/generation if used;
  - patch the owning session and payload/runtime snapshot;
  - project to DOM only if that owner is currently active;
  - ignore itself if stale.

It must not write to whichever component singleton is active when it resolves.

1.7 Capture and persistence contract
------------------------------------

Capture writes from the owning session into payload/runtime snapshots.

Capture must reject or skip owner mismatches. It must not read from a live DOM root
that belongs to another tab just because the component type matches.

File reopen must hydrate session from payload, then project into DOM only if the
session becomes active.

1.8 Render-cache and live-DOM reuse contract
--------------------------------------------

Same-component live-DOM reuse is an optimization, not a state source.

A reused DOM root is valid only if the root owner matches the tab being activated,
or if the component explicitly rebinds the root to the new owner and projects the
new owner's session before any capture.

Render-cache fragments must not restore stale graph/state geometry into a tab
unless the cache owner, payload signature, component type, and session generation
match.

1.9 DataViews/notes/managers contract
-------------------------------------

DataViews managers, notes controls, HOT managers, and auxiliary UI managers must
be owned by the tab session or by a documented owner-keyed registry.

Tests and component code must be able to resolve the manager for a tab without
relying on the currently active component singleton. If a manager is lazily
created, the creation path must take the owner tab id/session explicitly.

1.10 Module-global registry retirement contract
-----------------------------------------------

Old module-global control registries are a first-class refactor target and must
be removed or demoted whenever they can outlive the owning tab.

Examples include structures like:

  state.distributionInputs.checkboxes
  state.frequencyInputs
  state.statsInputs
  component-level refs/control registries
  module-level DataViews/notes/HOT mirrors
  cached render models not keyed by owner and data/settings signature

These registries are allowed only as transient DOM projection handles for the
currently active owner. They must not be the durable source of tab state and must
not be read for inactive tabs.

Required cleanup pattern:

  owning session state
      -> single projection helper updates the active DOM registry
      -> active DOM events patch the owning session immediately
      -> payload/runtime capture reads the owning session

Forbidden pattern:

  old module-global registry / visible DOM controls
      -> opportunistic capture
      -> guessed session/payload owner

When a persistent failure shows payload/session and visible controls disagree,
the next code change should remove or demote the responsible module-global
registry rather than adding a local synchronization guard.

1.11 Test contract
------------------

E2E tests should assert architectural invariants, not timing artifacts.

A test is valid when it waits for a settled owner state and then detects a
session/payload/DOM disagreement, an owner mismatch, stale result application,
or reopen-fidelity failure.

A test is suspect when it samples intentionally intermediate states: during draw,
layout, resize observer echoes, file hydration, passive live-DOM handoff, or async
loading. Such tests should be repaired by waiting for a stable owner contract,
not by weakening the expected final state.

2. LINE.JS POLICY
======================================================================

Line.js is not a blanket model and must not be copied wholesale.

It can be used only as an audited reference for specific patterns that are proven
clean. Candidate Line-like patterns to inspect and possibly reuse:

  - session-first label/title/legend updates;
  - explicit owner session scheduling;
  - no DOM/Event/session objects in serializable draw options;
  - inactive-tab payload/runtime capture from stored session state;
  - active DOM projection after owner session binding.

Line.js itself must be audited before it is cited as a model for any class of
change. If a Line pattern still depends on active mirrors or legacy globals, it
must not be propagated.

Roadmap requirement:
  Before the next broad component batch, add a short audit note identifying which
  Line patterns are safe references and which are legacy or irrelevant.

Selective Line.js audit note added in this stabilization package:
  Safe reference patterns to reuse conceptually, not copy mechanically:
    - owner/session binding before draw scheduling (`bindLineSessionForTab`,
      `bindLineInvocationSession`);
    - draw calls receiving owner-scoped metadata rather than raw DOM events;
    - payload/runtime capture paths that can target a tab/session explicitly.
  Patterns not to propagate without cleanup:
    - Line still contains large active mirrors and compatibility fallbacks;
    - Line has several call sites that consult `line.__boundTabId` as a bridge;
    - Line's size and legacy feature surface make it unsuitable as a wholesale
      component template.
  Operational rule:
    Use Line only as evidence for a specific already-audited pattern. The actual
    target for ROC/Histogram/Heatmap remains the architecture contract in
    Section 1: session canonical after hydration, DOM projection only,
    workspace-active owner resolution first, and serializable scheduler metadata.

5. COMPONENT IMPLEMENTATION TEMPLATE
======================================================================

Every component should converge toward this shape. Names may differ, but the
contract must be equivalent.

5.1 Session lookup
------------------

  getSessionForTab(tabId)
  getSessionForEvent(eventOrTarget)
  getActiveSession()

Rules:
  - `getActiveSession()` resolves workspace-active tab first.
  - It may fall back to a compatibility active mirror only before a tab exists.
  - It must never silently return another same-type tab session during activation.

5.2 Payload hydration
---------------------

  hydrateSessionFromPayload(session, payload, reason)

Rules:
  - plain data only;
  - no DOM reads;
  - no draw scheduling unless explicitly requested after hydration;
  - no active mirror writes except through `bindSessionToActive`.

5.3 Active binding and projection
---------------------------------

  bindSessionToActive(session, { reason, projectControls = true })
  projectSessionToDom(session, { reason })

Rules:
  - bind active mirrors from session;
  - project visible controls from session;
  - never read visible controls to create durable state during activation;
  - reject owner mismatch.

5.4 Event handlers
------------------

  bindControlHandler(element, eventName, handler)

Handler flow:

  const session = getSessionForEvent(event);
  patchSession(session, plainPatch);
  commitSessionToPayload(session, reason);
  scheduleDrawForSession(session, { tabId: session.tabId, reason, flags });

Rules:
  - do not patch module globals first;
  - do not rely on later capture;
  - do not pass Event/DOM/session/manager objects to schedule options.

5.5 Draw scheduling
-------------------

  scheduleDrawForSession(session, options)

Rules:
  - options must be sanitized plain data;
  - inactive sessions store pending draw options in session.timers or runtime;
  - active sessions project and draw only after owner check.

5.6 Capture
-----------

  captureSessionState(session, { reason })
  capturePayloadForTab(tabId, { reason })

Rules:
  - capture from session first;
  - active DOM may be read only if root/session/workspace owner all match;
  - inactive tabs never read DOM;
  - payload snapshots are plain serializable objects.

6.3 Test triage checklist
-------------------------

Before changing component code, answer:

  1. What final architectural invariant does the test assert?
  2. Does the test wait for a settled owner state?
  3. Are session, payload, and DOM expected to agree at that point?
  4. Is the observed value a legitimate final state or an intermediate draw?
  5. Is the failure reproduced in both trace/video and a direct state snapshot?

If the test checks a final session/payload/DOM disagreement after a settled state,
assume the component is wrong until proven otherwise.

If the test samples during a documented intermediate draw/resize/hydration phase,
fix the test wait instead of weakening the expected final state.

6.4 Do not count progress by audit finding counts alone
------------------------------------------------------

Static audit finding counts are useful for triage, but the real acceptance
criterion is dynamic browser behavior:
  - same-component tab switch;
  - inactive async completion;
  - duplicate/reuse;
  - archive save/reopen;
  - crash recovery;
  - DataViews/notes/control manager owner lookup;
  - no console critical errors.

9. DEFINITION OF DONE FOR THIS REFACTOR
======================================================================

The refactor is done only when all of the following hold:

  1. Every component has a documented session ownership contract.
  2. Payload hydration and live session ownership are clearly separated.
  3. DOM is projection only for durable state.
  4. Inactive tabs never read live DOM or active managers.
  5. Scheduled work is owner-scoped and serializable.
  6. Async/worker/timer callbacks are owner-tokened and stale-safe.
  7. DataViews/notes/HOT managers are owner-session or owner-registry based.
  8. Compatibility active mirrors have been deleted or documented as transient.
  9. Routine E2E gates pass without excluding any non-parked blocker.
 10. Archive reopen and crash recovery preserve full component state.
 11. No critical console errors are emitted in the owner/reopen gates.
 12. The Venn GO/STRING blocker is either fixed and admitted into routine gates or
     explicitly deferred outside the main refactor scope with a separate ticket.

CURRENT STABILIZATION NOTE - HISTOGRAM AND HEATMAP
======================================================================

2026-06-28 stabilization direction:

Histogram remaining blocker:
  The old distribution checkbox registry can remain projected from a previous
  Histogram tab even when payload/session distributions are correct. The fix is
  to make the session distribution settings canonical and rebuild/project the
  distribution checkbox list from that session during activation, reopen, and
  payload application. The registry is only a visible DOM handle, not state.

Heatmap remaining blocker:
  A view switch from correlation to values can update controls while a cached
  correlation render model or view-only resizer redraw remains operational. The
  fix is to invalidate model-family render caches and suppress programmatic
  lock-ratio event echoes when the heatmap view family changes. The full owner
  draw for the new view becomes the only draw allowed to advance the stable
  render model.

2026-06-28 - Priority 0 registry-retirement pass:
- Histogram: removed the old `state.distributionInputs`, `state.frequencyInputs`, and `state.statsInputs` module-global registries from `hist.js`. Distribution checkboxes are now rebuilt and projected from the owning session's `distributionSettings`; frequency and stats controls are queried/projected on demand instead of stored as state-like globals. The durable source remains the owner session/payload, not the visible checkbox/select registry.
- Heatmap: removed the unowned module-level `pendingDrawOptions` and `deferredHiddenDrawOptions` mirrors. Pending/deferred draw options now live only in the owner session's draw runtime. `state.lastRenderModel` has been removed as an owned cache; `heatmap.__getState()` projects `lastRenderModel` from the active owner session render runtime for diagnostics/tests. Stale skipped view-only redraws no longer advance the draw timestamp, and user view-family changes trigger a full owner draw that supersedes old correlation caches.
- This pass intentionally removes or demotes code rather than adding more guards around the old registries. Browser validation is still required for Histogram density/distribution reopen and Heatmap correlation-to-values view switching.
