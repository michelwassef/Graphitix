# Open Issues (Reviewed 2026-07-12)
# Actionable backlog only. Resolved, stale, duplicate, speculative, and metric-only entries are intentionally excluded.
# Ordered by descending priority. Every item must describe a verified current condition and a concrete completion contract.

[open][P1][2026-07-12] Remaining user-data and visual-control mutations do not yet all use one authoritative payload write-through contract. The restore refactor completed the shared save/recovery checkpoint transaction and normalized AG Grid cell/row/column exclusions to exact owner-scoped payload updates; however, programmatic `hot.loadData()` imports and several component style callbacks can still rely on the checkpoint's final live capture instead of updating canonical state at mutation time. Migrate those remaining paths to one owner-scoped mutation API that records user-vs-system source, updates `tab.payload` synchronously, marks only the owning tab/session dirty when appropriate, invalidates matching render caches, and schedules recovery from the new payload signature. Reopen/apply operations must remain non-dirty. Add import, example-load, style-edit, autosave-recovery, archive-reopen, and same-component two-tab isolation tests before removing the shared live-capture safety barrier.

[open][P1][2026-07-12] Heavy mixed Box/Scatter archive and recovery restores are not fully certified for warm-cache retention and first-interaction parity. Evidence: the heavy mixed diagnostics remain explicitly `test.fixme` in `e2e/box-scatter.render-cache-lifecycle.diagnostic.spec.js` and `e2e/heavy.mixed-tabs.reopen-recovery.canvas.spec.js`. Resolve the underlying cache-retention/hydration defect rather than weakening those assertions: restored visuals must be immediately interactive, computational and bitmap caches must remain owner-scoped and reusable, the first graph edit must not stall or publish stale work, and any payload-affecting edit must invalidate only the owning tab's cache. Unpark the existing archive and crash-recovery tests when the contract passes.

[open][P1][2026-07-12] Long render/statistics work still lacks one cooperative cancellation and atomic frame-publication contract across all components. `Shared.jobs` and loading-overlay integration exist for Scatter, Box, PCA, Line, Heatmap, Histogram, ROC, and Surface, but Venn, Pie, and Survival have no equivalent integration; worker task cancellation still primarily rejects stale results rather than cancelling a specific in-flight job. Introduce one tab-scoped render controller owning tokens, cancellation, worker task IDs, chunk/yield checkpoints, stop/retry UI, cleanup of unpublished frames, and idle/busy state used by save/recovery. Normalize Venn, Pie, and Survival to that contract and add large-dataset browser tests proving that cancellation remains clickable, stale work cannot publish, retry uses the same payload, and unrelated tabs remain responsive.

[open][P1][2026-07-12] Scatter large-point rendering remains a monolithic main-thread pipeline combining table collection, coordinate generation, style bucketing, canvas rasterization, SVG assembly, and cache publication. Refactor toward a state-first renderer with reusable typed coordinate/style buffers, a single canonical coordinate transform, optional OffscreenCanvas worker rasterization, and idle-deferred cache persistence. Preserve exact marker sprites, density quantization, device-pixel-ratio behavior, exports, and per-tab isolation. Keep headed-browser performance guards using `__tests__/test-scatter.csv` and assert both visual parity and main-thread responsiveness.

[open][P1][2026-07-12] Scatter still has side-effectful active-grid access and overly complex statistics draw suppression. `ensureScatterHotForActiveTab` can perform header/nested-header synchronization during access, while statistics scheduling contains defensive suppression state that is difficult to reason about across activation and restore. Move table/header writes to explicit mutation or projection-change events, make hot access read/ensure-only, and reduce statistics scheduling to the shared owner/token lifecycle contract. Add two-tab activation, inactive-tab stats completion, archive reopen, and crash-recovery regressions.

[open][P2][2026-07-12] Cross-component real-browser restore tests do not yet prove rendered visual parity for all persisted controls. For each component, set non-default colors and representative checkbox/text/geometry options, switch to a same-component sibling, reopen an archive, restore recovery, and assert rendered output as well as payload values. Keep component-specific assertions only where a shared semantic assertion is impossible.

Remove the DOM-command fallback only after desktop menu tests cover every component, inactive-tab safety, cancelled file selection, and unsaved-state behavior.

[open][P2][2026-07-12] Component control binding is duplicated across ten component-local `bind*ControlHandler` implementations with subtly different owner/session adaptation. Introduce a shared owner-aware deduplicating binder that stores binding identity per node, resolves the current owner at dispatch time, supports teardown/rebind, and never captures another tab's session. Migrate one component family at a time with same-component two-tab tests; do not mechanically replace the existing binders without preserving their component-specific event semantics.
