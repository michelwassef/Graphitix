# 2026-08-23 recheck: the P1 crash-recovery revision-loss finding is source-resolved and removed from the actionable backlog. `documentState.js` now maintains a lightweight recovery journal that persists the canonical per-tab payload/layout/uiState of every live tab with a short (400 ms) trailing coalesce on the mutation path (no previews/render caches), records the session revision on every rich snapshot, folds journal entries newer than the snapshot into the restore as a merged parsed session, and restores journal-only workspaces when the process died before the first debounced checkpoint. Journal writes are trimmed when a rich snapshot covers their revision and are cleared with the snapshot tier. Jest coverage proves coalescing, trim, stale-snapshot overlay, journal-only restore, and clean/lifecycle gating. Browser-level forced-termination certification remains an open P3 gap below.

[open][P3][2026-08-23] Browser-level forced-termination certification for the recovery journal is still open: the Jest suites prove journal scheduling/coalescing, rich-snapshot trim, stale-snapshot overlay, journal-only restore, and clean/lifecycle gating, but no Playwright spec yet kills the renderer inside the debounce window (immediately after an edit, during rapid continuous controls, across tab switches, and with owner-specific cache invalidation) and asserts the journal-overlay restore. [open][P2][2026-08-21] Venn's asynchronous UniProt region tooltip is not owner-bound. `handleRegionListMouseover()` (`js/components/venn.js:11806`) captures a gene, awaits `fetchUniProtAnnotation()`, then writes/positions the singleton tooltip against the then-current Venn projection. Switching A→B during the request can display A's annotation in B. Capture the originating tab/root/session generation from the event before the await, discard stale completions, keep tooltip state owner-scoped, and test A→B and A→B→A hover races.

[open][P2][2026-08-21] Box and Scatter file-import cancel/empty/error completion can settle the wrong sibling loading overlay even though the shared table-import data mutation itself is owner-safe. Box's trailing Promise handlers around `js/components/box.js:18966-18971` and Scatter's around `js/components/scatter.js:28843-28848` call their loading-overlay resolver without preserving the original import tab ID; after A→B, cleanup can target B's controller key and leave A pending when revisited. Preserve the import owner through every completion path, normalize with the safer owner-aware importer/Histogram pattern, and add same-component success/empty/error/cancel switch-race tests. Treat this as transient UI ownership, not a durable data leak.

[open][P2][2026-08-21] `Shared.componentLifecycle.resolveOwnedObjectTabId()` (`js/shared/componentLifecycle.js:235-290`) accepts generic `.id` fields on owners and nested objects before validating that the value is an actual workspace tab identity. An unstamped DOM/component object such as an element whose id is `scatterPage` can therefore be interpreted as a tab ID, weakening ownership inference in shared helpers. Restrict ownership inference to explicit ownership stamps and validated workspace/session records; never accept arbitrary DOM/object `.id` as sufficient evidence. Add contract tests for unstamped DOM nodes, nested managers/DataViews, stale/wrong-component objects, and legitimate stamped owners.

[open][P2][2026-08-21] Surface fast-rotation cache geometry is serializable and owner-correct but unnecessarily duplicates dense mesh coordinates. The rotation model stores a full `points` list plus face objects containing repeated vertex point objects, and `captureRenderCache()` clones that model in addition to canonical table data and the SVG cache. Replace face vertices with indexed connectivity or another compact deterministic serializable representation, rebuild transient rotation pools after restore, and add archive-size/memory plus first-rotation performance regressions for the largest supported grids without changing reopen fidelity or owner boundaries.

[open][P2][2026-08-21] `Shared.componentLifecycle` still has only a coarse render-impact contract: `mergeDrawOptions()` mainly merges `viewOnly` versus full/structural work and combines `viewOnly` by boolean AND, while component controls continue to call component schedulers directly. This makes local paint/layer changes liable to coalesce into broader redraws and keeps invalidation semantics component-specific. Introduce an owner-scoped, plain-serializable semantic invalidation model (state-only/paint/named layers/layout/scales/analysis/structural) with union merge semantics and full-render fallback; migrate shared controls then component-specific controls incrementally; preserve synchronous canonical write-through and immediate owner cache invalidation; and extend redraw auditing so persisted controls declare and are tested against their maximum allowed render impact. This is an architecture/performance issue, not evidence of current cross-tab corruption.

[open][P3][2026-08-21] Multiple components retain local p-value formatting fallbacks after first attempting the shared reporting/formatter API (Line, Scatter, Box, Histogram, Pie, ROC, Survival). [open][P3][2026-08-21] Shared p-value formatting silently clamps finite inputs outside the valid probability range `[0, 1]` before presentation. A negative upstream result is therefore displayed as an extreme valid probability instead of exposing the statistical defect, while values above one become `1`. Define one invalid-probability reporting contract, return an explicit unavailable/error state for out-of-range inputs, and add shared/component tests without weakening the separate floating-point underflow threshold behavior for a legitimate zero result.
