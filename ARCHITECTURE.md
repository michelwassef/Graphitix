# Architecture Guide

This file is the fast-orientation entrypoint for the Graphitix codebase. It complements [README.md](./README.md), [docs/development/main-bootstrap.md](./docs/development/main-bootstrap.md), and the generated [docs/development/module-call-map.md](./docs/development/module-call-map.md).

For component-level contracts, see the generated [docs/development/component-contracts.md](./docs/development/component-contracts.md).

Contextual Format toolbars mount complete panels through `Shared.workspaceToolbar.mountPanels(host, panels, options)`. Replacement is the default; intentional combined toolbars explicitly append panels or supply their complete ordered panel set. Providers never remove another panel's inner fields. Shared host activation continues to own visibility, owner metadata, section activation, and overflow; component sessions remain the authority for edited values.

Box, Line, and Scatter save axis/index identity on additional reference lines. `Shared.additionalLineControls` rebuilds their handlers from the active owner's axis settings after cache restore; caches without identity are rejected so the normal payload draw restores the graph and its controls.

Visualization workspaces share a responsive content grid. The outer `workspace-graph-panel` participates only in the persisted table/graph split; its `workspace-graph-content` child owns padding, scrolling, and the `workspace-graph` size container. At 600 CSS pixels of content width and above, the figure uses its natural display width and controls fill the remaining width with a 300-pixel minimum and 600-pixel maximum; the control panel stays left-aligned when it reaches that cap. The controls narrow as the figure grows. Once they reach 300 pixels, the shared content track expands and the whole right pane scrolls horizontally. Statistics shares that track and spans its full width. Below 600 CSS pixels, controls move below the figure and their fieldsets wrap. The named, keyboard-focusable `workspace-graph-content` region owns horizontal scrolling; `workspace-plot-region` keeps the figure, export footer, and notes together without a local scrollbar. These wrappers are display layout, never inputs to canonical figure dimensions or exports.

Box symbol borders use `Shared.svgGeometry.applyInnerStroke`: canonical outlines stay fixed while double-width SVG strokes are clipped inward. Formatting reads and writes semantic thickness through the same helper; individual point borders retain their existing behavior. Box comparison levels retain their computed coordinates, and the content envelope expands to contain their labels; annotations are never clamped to a fixed top boundary. Box render-cache metadata versions the complete render geometry so older border/annotation fragments redraw from owner state. PDF and EMF scenes preserve transformed, nested rectangular/path clips as native clipping operations, including clipping strokes and restoring the clip before siblings.

## 1. Runtime Bootstrap Order

`index.html` loads scripts in a strict sequence. The order matters because modules attach to global namespaces (`window.Shared`, `window.Main`, `window.Components`) and expect prior modules to exist.

1. External libs (`ag-grid`, `jStat`)
2. Core vendor shim (`js/vendor.js`)
3. Shared utilities (`js/shared/*.js`)
4. Main namespace modules (`js/main/*.js`, `js/main/tabs/*.js`)
5. Root bootstrap (`js/main.js`)

The exact ordered deferred script list is near the top of `index.html`, around lines 61-161. See [main-bootstrap.md](./docs/development/main-bootstrap.md) for the loading sequence and its checks.

After the main control plane starts, `Main.components` loads visualization modules on demand. The descriptors in [`js/main/components.js`](./js/main/components.js) give each workspace type a browser dynamic-import path and a Node `require` path; the component file registers itself as `window.Components[type]`. These are the current classic-script/CommonJS conventions, not named-export ES modules. Keep both paths pointed at the same component source and use the loader rather than adding component script tags. The component-contract check validates the source/registration boundary, and a Chromium contract exercises every workspace bundle.

## 2. Namespace Ownership

Box and Scatter construct complete live session records in their session factories. Existing-session lookup returns those records by identity; it does not rebuild refs, runtime caches, advisor/state slices or inspect DOM connectedness. Payload/runtime hydration normalizes incoming state at its explicit boundary. DOM-reference validation remains in binding, reference assignment and snapshot/capture helpers. This keeps pending work and canonical owner objects stable during repeated reads.

Scatter's data-aware palette override is durable owner state. Hydration imports it from the payload, paste decisions read the owning session, and payload capture serializes it from that same session. The label-distribution policy remains independent: repeated points within a category remain grouped, while unique point labels retain the grayscale rule.

- `window.Shared`

Their complete IDs use the existing owner-scoped `colorScheme` payload field, including Venn's `style.colorScheme`; original IDs retain their saved color definitions. Palette actions preserve existing category positions, while appearance actions retain custom fills, transparency, and quantitative value scales. The shared delegated controls survive cloned workspace roots and reject events from another owner. Palette capacity and low contrast are disclosed; palette selection alone is not an accessibility guarantee.
  - Source of truth for reusable services: grid wiring, file IO, import/export, styling, stats, resizers, analysis integrations.
  - `Shared.modalLifecycle` owns stacked DOM dialogs, focus containment/restoration, background inerting, scroll locking, and registered Escape behavior. Prompt modules provide their initial focus and close policy; they do not implement parallel focus traps.

Apply resolves a fresh plan, rejects retired controls, and commits settings to the owner before projecting controls. Owner-specific radio groups and focus restoration preserve keyboard navigation. During active development, inference hydration is current-schema only: do not revive retired component-local alpha/threshold fields or add compatibility migrations for obsolete payloads. Confidence levels remain independent unless the statistical procedure mathematically derives simultaneous intervals from α. FDR results are described as discoveries (with `D`/`ND` compact decision markers), not significance stars. Assumption diagnostics use their own diagnostic threshold and may inform the user, but must never auto-select parametric/non-parametric or pooled/Welch analysis branches.

Measurement is bound to the SVG being committed, including staged renderers. Non-axis renderers may provide an explicit content measurement, as Heatmap Data values does for its matrix.

Display-only zoom projects the stored frame without running resize constraints or rewriting its aspect ratio. `Shared.axisControls.measureCanonicalAxes()` is the boundary for renderer-specific editors such as PCA 2D; `measureRenderedAxes()` deliberately retains screen pixels for ratio locking and viewport enforcement. Toolbar readouts report measured geometry rather than temporary requested-value dataset caches. Refinement awaits the owning component's settled publication and rechecks the owner/generation after that wait before applying another resize.
  - Ratio locking is a tab-owned resize constraint: toggling and handle clicks without movement are geometry-neutral, Cartesian targets use rendered axis lengths, and component resize callbacks are the sole draw-request owner. Automatic content-reserve sizing uses transient resizer authority and must not mark the graph as manually resized.
  - `Shared.cartesianLayout` is the geometry authority for migrated 2D axis renderers. A single owner/generation-scoped transaction keeps `userFrame` (canonical persisted/manual size), `plotRect` (data-coordinate geometry), and `contentEnvelope` (derived visible/export extent) distinct; measured labels, significance, risk tables, panel rails, metric overflow, and legends cannot feed their derived envelope back into the canonical frame. The resizer consumes the committed rendered-axis Lock target from that same plan and does not run legacy post-render calibration for migrated modes. Current adapters cover Line/Scatter 2D, ROC/PR, Survival, Histogram overlay/panels, stacked Pie, Box, and PCA 2D; 3D modes, Heatmap, Venn/UpSet, and radial Pie/Donut modes retain their renderer-specific contracts. Every graph uses one shared `.graph-frame` presentation wrapper: `.graph-controls-header` is normal-flow UI above the existing `.svgbox`, while Download/Copy remains below it. The wrapper and header are presentation only; `.svgbox` remains the sizing, owner, zoom, and content-envelope boundary, and controls never participate in `userFrame`, `plotRect`, or `contentEnvelope` measurement. The graph body no longer reserves the legacy controls tray inset; its actual box model supplies the drawable frame.
  - Graph resize grips follow the published graph/content-envelope edges, independently of the outer controls frame. A transient guide reveals a detached resize boundary during graph-area hover, size-field focus, and dragging; its wrapper markers and CSS overlay never enter canonical sizing, SVG exports, or saved state.

The frame uses its own background and one inset outline. Layout capture does not write checkbox projections back over the resizer's published aspect state.
  - `Shared.chartStyle.stageGraphContentViewport()` publishes visible container space together with every content extension. Components cannot opt out of this projection, including Plot3D legends and restored caches. The complete envelope expands presentation space and handle positions; it never replaces the canonical graph dimensions or changes plot geometry.

Plot3D places the nearest painted title edge beyond the complete tick bounds with one `axisTitleGap`, using the standard Cartesian metric by default (3 SVG units at 16px). There is no second padding or estimated minimum offset. Its rotation-safe frame estimate uses the same gap, complete tick/title extents, and effective title font size. Additional title lines still extend the viewport by their exact line height.

Actual rotated text bounds select non-overlapping labels, prioritizing titles, longer projected axes, and endpoint ticks. This derived visibility never changes axis ranges, canonical dimensions, rotation, or saved label/font settings; redraw and cached rotation use the same policy. Surface scale reservation, rendering, and restored drag interactions use the canonical base frame, independently of multiline-title extensions.
  - `Shared.componentLayout` keeps graph-frame width/height as absolute document geometry, while serializing the table/graph workspace split as a tab-owned relative fraction. Reopen recalculates the split against the recipient viewport without imposing pane minimums; a small viewport scrolls the unchanged graph frame instead of importing the source computer's panel pixels.
  - `Shared.resizer` exposes the table/graph divider as a named vertical separator with a full 0–100% range. Pointer and keyboard resizing reach either collapsed endpoint; the split takes precedence over graph-frame width locks, and horizontal split projection is skipped in stacked layouts. Collapsed panes leave focus order and are hidden from accessibility APIs. Movable SVG labels and legends use owner-checked arrow-key movement through their existing persistence/undo callbacks, stop those keys before chart-mark navigation, and restore focus by logical item after SVG redraw.

Legend visibility cannot alter projector dimensions, margins, or shifts. `stagePlot3dViewport()` stores canonical graph dimensions separately from the full published viewport and restores both without counting the legend twice. `Shared.plot3d.FRAME_LAYOUT_VERSION` invalidates obsolete rotation/cache geometry so archive hydration rebuilds it from the owning session. Surface retains fixed scale dimensions and interprets legacy dragged positions through the shared legend-position resolver.

Component plot geometry must use the canonical base width; the legend extension is added only when the final SVG viewport is published. Legend content is excluded from automatic viewport fitting. Render-cache restoration rehydrates this derived envelope from SVG metadata without changing the cached viewBox or persisted graph size.

Primary workspace graphs resolve their canonical CSS-pixel size from the owning resizer/drawable frame; auxiliary graphs resolve from their own declared frame. Logical SVG `viewBox` geometry remains independent of physical output dimensions. Legend/content extensions enlarge the output canvas at the existing logical-to-physical scale instead of shrinking the base plot. SVG copy/download/hybrid, PNG, TIFF, PDF, and EMF consume the same projection. CSS pixels are interpreted at 96 DPI, PDF converts once at 72/96 points per pixel, and raster scale changes pixel density plus resolution metadata rather than physical size. Components may prepare graph-specific vector/raster content but must not independently choose export root width or height.
  - `Shared.exampleDatasets` is the single provenance authority for built-in biomedical examples. Registry records are deeply frozen and cloned per load; component loaders apply the cloned table plus owner-scoped Notes through their normal persistence contract rather than sharing mutable literals across tabs.
  - `Shared.tableImport` owns Prism/PZFX normalization. The `.prism` archive parser and `.pzfx` XML parser must first produce the same canonical Prism-table semantics (table type, row/X/Y series, raw subcolumns, exclusions, and source metadata) before any component adapter reshapes data. Component routing consumes explicit canonical `component`/`adapter` metadata; unknown or unsupported Prism semantics must never fall through to a default graph type. Raw XY, Column/OneWay, Grouped/TwoWay, Survival, and Parts-of-whole tables have lossless adapters today. Precomputed summary/error tables, independent X-error tables, Contingency, Multiple Variables, and Nested tables remain explicit unsupported cases until Graphitix has matching native data semantics.

PZFX Template sections are associated only for a single-table/single-graph pair or a uniquely titled table/graph pair with matching series records; ambiguous sections fail closed. The current style handoff only projects while the owner is active; the required session-owned inactive completion contract remains an explicit P1 architectural gap. Verified stored axis ranges are informational until axis visibility/automatic-scaling semantics and a shared owner-scoped axis adapter are implemented; ambiguous legacy PZFX graph metadata remains unassociated.
  - `Shared.svgGeometry` is the stateless geometry authority for homogeneous multi-segment SVG strokes. It converts exact line-segment geometry into independent compound-path subpaths and provides capped-line/cross segment builders; component renderers retain ownership of DOM creation, styling, interaction, persistence, and tab-scoped controls.

- `window.Components`
  - Visualization workspaces (`venn`, `box`, `scatter`, `surface`, `pca`, `line`, `heatmap`, `roc`, `survival`, `hist`, `pie`).
  - Each component owns UI bindings and graph-specific payload shape.
  - Closing a tab is a separate lifecycle transition from switching away. `workspaceTabs.disposeTab()` cancels the tab's async scopes and jobs before invoking component disposal and releasing its table, runtime, and shared-control records. Component disposers release only their owner's sessions and resources; they must not create a replacement session or affect same-type siblings.
  - Box grouped analysis `nestedRepeatedTwoWay` is a distinct, persisted two-way mixed ANOVA for independent groups with subjects nested within group and measured under exactly two conditions. It requires complete balanced numeric data; group uses subjects-within-group error, while condition and interaction use subjects-within-group-by-condition error. Keep it separate from the crossed `rowRandomMixed` model and block unsupported designs.
  - Box `rowRandomMixed` is a fully crossed within-subject Group × Condition ANOVA over complete subject rows. Group, Condition, and their interaction each use effect-specific contrast covariance; GG-corrected p-values are primary and HF results are supplementary. Saved results carry a method-versioned structured result; older row-random calculations restore as stale until recalculated.

Separate-panel mode publishes one `#histSvg` containing one panel group per series and one comparison X domain before rendering any panel; histograms additionally reuse pooled bin edges, while density panels evaluate every KDE on the common X domain. The Y scale may be shared or series-specific. Arrangement is presentation geometry (`auto`, `horizontal`, `vertical`, or `grid`) within that same SVG, not a collection of independent graph containers. Panel rows and columns are track-sized around one common plot width and height, so hidden interior tick labels reclaim their reserve without changing axis lengths. Automatic Y-tick capacity is based on text height and any thinning preserves a regular graduation. The panel-only control row is a DOM projection of the owner state and is never persisted separately. Runtime replay may seed `seriesLayout` only when no owner session exists; once the session is hydrated or live, a stale runtime projection cannot replace that canonical field. Switching between Histogram and Density preserves the exact panel contract rather than falling back to a different layout. ## 3. Main Session/Tab Control Plane

`Main.workspacePreparation` separates background preparation from live activation. After the shared normal-open/recovery transaction publishes the selected workspace and releases its document lock, idle work imports other component bundles, copies their saved payloads in bounded slices and deserializes validated graph caches into detached fragments. Its disposable registry is keyed by the exact tab object and document generation; entries also match payload/layout/cache references, signatures and publication versions. It retains at most four prepared tabs within an estimated 32 MiB budget. Preparation never invokes component ensure/init/activate, mounts roots, binds managers or changes active mirrors. An early click cancels unfinished preparation instead of waiting for it; completed copies are consumed once by the normal activation path. Tab disposal and a new document operation cancel owner work and release prepared copies. Live grids and graph interactions are still constructed by the active owner, with all existing cache eligibility and interaction checks intact. No worker has been added: these changes remove work from first activation without changing archive parsing.

Cold restored workspaces remain measurable and inert behind a loading surface until owner-scoped graph publication completes. `loadedWorkspaces` and `activate-complete` certify that final boundary, rather than merely payload projection. A monotonically increasing activation token protects the same-owner return case as well as cross-owner switching; lazy component loading verifies it before invoking setup, and activation verifies it again before committing. If the owning payload, layout or cache checkpoint changes during lazy loading, activation restarts from the latest canonical checkpoint rather than applying an earlier prepared copy. Failed activation retains its error state and is not marked loaded. A newer cold activation transfers the last committed visual surface while releasing only the previous live-root barrier; stale completions cannot release a newer activation, including a restart for the same owner. Missing or rejected caches use the existing single owner-scoped redraw path.

`Main.workspacePresentation` owns only transient presentation and bounded workload timing metadata. Before deactivation, cold-tab navigation retains the displayed workspace in an inert, accessibility-hidden shadow tree, with copied control values, scroll positions and canvas pixels. The shadow boundary preserves styling and prevents copied ids or grids from participating in document/component lookups; it never supplies session, cache, save or runtime state. Rapid switches transfer this same last completed view. The canonical active owner advances normally for safe hydration, while the tab strip projects the retained owner until publication commits the destination content and highlight together. Warm live-root reuse keeps its direct path.

Feedback is predicted once from the actual activation plan: loaded component bundle, reusable validated graph cache, prepared payload, estimated grid workload and bounded prior successful timings for equivalent component/path/workload buckets. Likely costly work displays a message immediately; likely fast work stays silent. There is no delay timer, minimum duration or readiness dependence on the prediction. Likely slow paths allow the browser to paint the immediate message before synchronous setup; fast paths do not yield. That paint opportunity is owner-cancellable and cannot strand background-tab restoration. Only successful completions train timings; cancellation and errors do not. New document operations clear timings and presentation, owner disposal releases only its own pending activation, and errors retain the previous view with an immediate alert. Predictions can be wrong; publication, ownership and interaction barriers remain identical in either case.

Primary state lives in `js/main/session.js`:

Panel widths and content envelopes do not affect default zoom. Manual zoom and resizing replace fit intent; resize undo restores it. Existing archives retain their saved sizes and numeric zoom. See [state-persistence-schema.md](docs/development/state-persistence-schema.md) for the layout contract.

## 4. Component Contract (What Main Expects)

Each workspace component should expose these (directly or via equivalent wrapper in `Main.components.registry`):

- `ensure()` or `init()`
- `draw()`
- `getPayload()`
- `loadFromPayload(payload, options)`
- `createEmptyPayload()`

For DataView-enabled components, `payload.data` is always the canonical **Raw** table matrix, even when a derived DataView is currently active. The displayed projection is identified by `activeDataViewId` / `dataViews.activeViewId`; serialized derived matrices, transform specifications, and replay execution options belong under `dataViews`. `Shared.dataViewPersistence.resolveRawDataForPersistence()` is the common authority used by component payload capture, shared table write-through, and both `.graph` archive builders. User edits to a derived table update that DataView but must leave top-level `payload.data` on Raw. Lite/adaptive archives store the Raw matrix in `raw/data.csv` and omit only derived matrices that the archive loader can deterministically replay from a supported serialized transform plus the exact serialized execution options that originally produced the view. Specialized/materialized derived views, derived views whose replay inputs are incomplete, and derived views changed by direct user table edits retain their matrices inline so reopen remains exact. Any matrix mutation of a source view must also invalidate replayability recursively for every already-materialized descendant, because those descendants represent the pre-mutation source state; component-generated matrix refreshes must use the same `Shared.dataViews` mutation boundary rather than assigning view `.data` directly. A component must never promote the active derived projection into top-level `payload.data`.

Optional but already supported:

- `activateTab(tab, meta)`
- `captureRenderCache(meta)` / `restoreRenderCache(cache, meta)`
- `rehydrateGraphInteractions(meta)`
- `hasRenderablePayload(payload, meta)` distinguishes persisted user/table state from data that should publish a primary graph. It must be pure, exclusion-aware, DataView-aware, and component-specific; restore must not infer graph publication from generic non-empty cells.
- `hasRenderedGraph(meta)` for an authoritative publication check scoped to the component's primary graph surface and, where available, its component-owned data marks. Axes, grids, statistics plots, toolbar icons, scree plots, and other auxiliary SVG/canvas content must not satisfy this contract.
  Renderer-owned semantic publication marks are authoritative even when transient DOM geometry is zero during deactivation or in non-layout test environments; publication checks must not require a measurable bounding box when the component can prove completion semantically.

Render-cache validation is split deliberately: the component owns semantic completeness and embedded cache provenance (`type`, owner tab, `complete`), while shared orchestration owns archive wrapper signatures and activation order. `canRestoreRenderCache()` must be a pure, projection-free eligibility check; it must not reject a complete exact cache merely because another tab currently owns the visible module projection or because a presentation state already contained in the cached graph is non-default. `restoreRenderCache()` remains the owner-guarded DOM mutation boundary. After DOM restore, shared font interactions and the component's `rehydrateGraphInteractions()` hook must bind successfully before the cache is accepted; otherwise shared orchestration rejects it and rebuilds before user input. Imperative interactions that cannot survive DOM serialization must leave durable semantic markers (currently `data-axis-control`/axis metadata, `data-inline-editable`, and keyboard-movable SVG label metadata). Positionable graph titles and axis titles serialize their relative-position metrics; axis titles also declare a `data-label-drag-position-key`. Scatter/PCA point labels serialize their point anchor, leader geometry inputs, and text/container metrics; `Shared.labelLayout.rehydratePointLabelDrags()` restores their pointer/keyboard handlers through the exact owner session. A legacy point-label cache without those metrics is rejected and redrawn from the owning payload. `Shared.rehydrateLabelDrag()` and `Shared.rehydrateLabelDrags()` rebuild title/axis handlers, and each binding records its owner tab id. Shared lifecycle validation verifies declared bindings and owner ids after component rehydration; a hook returning success is not sufficient on its own. A first user edit must never be used as an interaction-rehydration trigger. Graph caches must not serialize statistics/control DOM whose listeners cannot survive serialization; rebuild those surfaces from durable owner state after graph hydration.

Archive `tab.json` also carries paths and values for non-enumerable `__graphitixMatrixSignature` markers. The archive CSV and JSON paths cannot preserve those array properties themselves; the parser restores them before session payload/cache provenance is checked, and session tab staging restores them after cloning. The main-thread and worker archive writers use the same metadata contract so full, lite, and worker-built archives keep exact cache signatures.

Passive DOM projection is valid only after a component has completed full initialization for an owner session. Component ensure and activation both enforce this boundary: a newly imported or otherwise uninitialized component must create its table, layout, schedulers, and owner-scoped runtime first; draw suppression during restore does not permit marking a partial bind as `ready`.

An authoritative `draw(meta)` must return its real synchronous result or Promise. Registry wrappers must not detach completion behind a second scheduler. When a renderer replaces its own frame recursively (for example, a layout reflow), the superseded render must transfer ownership explicitly so its cleanup cannot invalidate the replacement frame.

Async SVG renderers must stage replacement frames through `Shared.framePublication`, finalize their viewport, perform a final owner/job check, and only then commit. They must not clear or mutate the committed graph before that boundary.

Publication presets are live presentation edits. They use the existing component `loadFromPayload` style projection contract (`styleOnly`, `skipDataLoad`, `viewOnly`, and `publicationStyle`), followed by owner-scoped shared sizing. Style projection must retain table instances, data-view managers and materialized views, numerical results, notes and responsive sizing baselines; it must not deserialize data views or restore archive statistics. Box's publication projection includes font styles, visibility and significance styling in addition to palette paint. Full file/reopen hydration remains a separate path.

### Workspace toolbar overflow and popup projection

`Shared.workspaceToolbar` remains the authority for toolbar sections, contextual Format hosts, active-section state, and owner resolution. `Shared.toolbarOverflow` is a presentation-only adapter attached to the rendered toolbar:

Aggregate style undo uses `Shared.styleUndo` atomic snapshots when a component exposes `aggregateUndo.capture/apply`. The snapshot is complete owner state, not a repeated scalar value; undo and redo restore it with one owner callback and one redraw regardless of target count. Controls without an atomic owner contract retain the exact per-scope fallback. High-cardinality controls must implement the atomic contract rather than replaying one mutation per point.

`Shared.fontControls.markText()` accepts reusable named collections through `collection` and `collectionLabel`. A selected member exposes that collection beside Selection and Graph; collection styles use the same tab-owned persistence, undo, redraw, restore, and export path as the built-in Labels, Legend, and Scale scopes.

- Every General, Data, and Format section has one horizontal viewport and one track. The adapter wraps the section's existing children once; it never clones controls, duplicates event handlers, or moves actions into a second menu/state surface.
- Overflow is determined from the section's natural content width versus its available shell width. Directional chevrons and edge fades reflect only the currently hidden direction, and item-aware scrolling reveals the next clipped control or contextual panel.
- Native touch/trackpad horizontal scrolling remains available. Shift+wheel is the only vertical-wheel translation, and keyboard focus automatically reveals an offscreen control without intercepting arrow keys needed by inputs, selects, and sliders.
- Raw `scrollLeft` is transient projection state. It resets when the active toolbar section or owning workspace tab changes and is never persisted into `tab.uiState` or `.graph` archives. The stable active section ID is persisted and restored through `workspaceToolbar.activateSectionById()`.
- Toolbar popups that would otherwise be clipped by the horizontal viewport use `Shared.toolbarOverflow.positionPopup()`. The original popup node remains under its owner control, is positioned against its trigger in viewport coordinates, reads its default stacking layer from `--ui-layer-floating-overlay`, and has its prior inline styles restored on close. An explicit per-popup z-index remains supported. Components and shared controls must not introduce separate overflow-specific popup copies.
- Overflow state is keyed by concrete toolbar/section DOM nodes in `WeakMap`s. No process-global active toolbar, owner, or scroll offset is authoritative.

## 5. Persistence Flow

Graphitix has one document checkpoint transaction and one document restore transaction. Manual file operations and private crash recovery differ only in destination metadata; they use the same authoritative payload, layout, preview, and render-cache contract and do not own separate hydration logic.

### Checkpoint and serialization

1. `Main.sessionActions.createDocumentCheckpoint()` resolves the snapshot policy, waits for the active component's snapshot-ready contract, and captures the active live payload through `Main.session.persistActiveTabState()` with save-grade intent. Snapshot readiness is publication-settled: the owner must report idle **and** `Shared.framePublication` must have no staged replacement frame for that component/tab. A timed-out or unsettled owner rejects manual/recovery checkpoint capture; autosave defers without replacing the last valid snapshot.
2. `Main.sessionActions.buildScopeSnapshot()` clones the already committed payload, layout, `uiState`, preview metadata, and only render caches whose owner, component, payload signature, and layout signature exactly match that detached checkpoint snapshot. Archive construction never re-enriches or mutates canonical payload/layout after cache capture and never manufactures a cache by cloning mounted DOM. The owner-captured layout is authoritative; payload `meta.graphSizing.display` is a compatibility mirror of display/layout sizing only and must never be merged back over an existing canonical layout; export dimensions are never persisted there and are resolved on demand by `Shared.exportProjection`. When no canonical layout exists, payload sizing may seed a default layout template; explicit finite or unlimited payload bounds override that template, while omitted bound policy preserves the template's defaults. Completed component-owned captures maintain an archive-ready serialized checkpoint, so warm runtime-cache pruning cannot remove a valid cache from later manual-save or crash-recovery snapshots.
   `Shared.renderCacheSchema` is the sole owner/component provenance parser. New captures must carry exact version-3 component-owned metadata and are validated before shared presentation metadata is added; shared code must never rewrite `tabId`, `component`, `type`, or `complete`. Older schema versions open through canonical payload redraw and are never copied into a new archive.
   When an owner explicitly marks a payload update as render-equivalent, the session boundary advances embedded Cartesian payload provenance together with the cache envelope signature while retaining the valid geometry. This is an explicit component contract, not a general cache relabelling fallback.
   A render-cache capture may establish the current render-commit checkpoint only after the same publication-settled predicate succeeds. Atomic renderers may keep the previous committed frame visible while a replacement is staged, but that previous frame must never be captured and stamped with the replacement payload/layout versions. Snapshot readiness and render-cache currentness are separate contracts: `awaitReadyForSnapshot()` / `isIdleForSnapshot()` answer whether owner state is safe to serialize, while optional `isRenderCacheCurrent(meta)` answers whether the currently published graph represents that canonical payload. A manual-render component may therefore save its newer canonical payload while deliberately omitting an older stale render cache. Shared capture clears both cache tiers when currentness is false; it must never block the document checkpoint merely because the user has chosen not to redraw yet.
   Pending heavy tab previews are awaited first. Their single PNG image is committed only when the owner, payload, layout, and generation still match. Preview capture is presentation metadata only and never advances the graph render-commit checkpoint. Shared session payload assignment clears a prior preview when the newly assigned canonical payload is explicitly non-renderable and suppresses stale-DOM recapture for that exact payload revision; transient missing DOM alone must not clear a stored preview.
3. `Main.sessionActions.serializeDocumentCheckpoint()` is the only archive serialization entry for a detached checkpoint snapshot.
4. Manual Save and crash recovery both include every exact owner-scoped completed cache checkpoint and capture the active owner only when its current checkpoint is missing or stale. Autosave remains intentionally cache-free. No checkpoint path activates inactive tabs to manufacture caches.

Component runtime/internal snapshots are JSON-compatible structural clones, not graph traversals that deduplicate repeated references. Shared snapshot sanitization treats object tracking as a recursion stack: a true cycle is removed, but the same durable object referenced from multiple fields is cloned at every field. Array length and indexes are semantic and must be preserved; removing a transient/uncloneable array entry uses `null` rather than compacting later entries. When a component's explicit owner runtime snapshot already owns a durable statistics/report model, that field is excluded from the generic internal-state bridge so a second projection owner cannot overwrite the canonical model during restore.

The internal-state bridge retains compatibility snapshots in the owning session's lifecycle runtime snapshot (`__internalState`). It reads or applies module targets only when the workspace-active owner, component binding, and mounted root agree. Inactive capture reads that owner's stored snapshot; inactive restore hydrates the native owner session and stores compatibility state without changing the mounted sibling. Native restore methods follow the same storage-before-projection boundary. Runtime methods must be declared before bridge installation; initialization must not replace wrapped methods. Async restore projects compatibility state only after successful native settlement and a fresh ownership check.

Transient draw ownership follows one queue contract per owner. Accepted/running work is represented separately from at most one deferred replay request; optional queue slots remain `null` when absent and must never be passed through a sanitizer that manufactures default draw options. Deactivation may move the exact accepted request into the owner deferred slot, and activation consumes that slot only for the same owner/session. Durable runtime hydration must not clear or reconstruct these scheduler fields. Manual AutoDraw `drawPending` means canonical edits await a user-requested render; it is not an async publication token and therefore participates in render-cache currentness, not snapshot-idle state.

Same-component runtime/payload capture follows the same owner agreement as activation: the requested tab, workspace-active tab, projected session/root, and component session must agree before controls, HOT, module mirrors, or rendered statistics DOM may be read. If they do not agree, capture uses the requested owner's stored session/runtime/payload state verbatim. A visible statistics/report panel is a projection, never a durable source of truth.

The significance toolbar owns one shared Label selector alongside its style, whisker and number-format controls. Box supplies session-bound getters and mutations, not tab-owned DOM controls. Every significance edit writes the originating session, runtime snapshot and payload; inactive undo can update that owner without reading or changing the active projection. Picker and drag work retain their initiating configuration and cannot retarget another tab. Cached comparison labels restore their combined comparison/font interactions before edits are accepted.

Live module/DOM authority is stricter than activation intent. `Shared.componentLifecycle.canOwnerUseLiveProjection()` is the common gate for any read or write of component module mirrors, live refs/managers, mounted controls, HOT/DataView projections, callback-owned DOM, or live render/cache state. It requires the requested owner, workspace component owner, component projection id, owner session id, and the **registered mounted root**, its connected DOM identity, and its owner stamp to agree. During a same-component handoff it is valid for the workspace active tab to advance before the mounted projection changes; in that gap neither the outgoing nor incoming owner may consume live module/DOM state. `Shared.componentLifecycle.isOwnerActivationTarget()` is deliberately separate and may be used only to decide which owner should be scheduled/deferred/hydrated next; it never authorizes live capture. This distinction also prevents ABA reactivation from reviving stale live authority merely because the workspace returns to the same tab id.

Component-enforced layout policies (for example, correlation Heatmap forcing Lock ratio) run after generic layout/resizer restoration and before canonical layout capture. The component policy must drive the shared resizer API and all persisted aspect-lock aliases together; generic layout state must not leave contradictory `resizerAspectLocked`, `graphAspectLocked`, and legacy `aspectLocked` values.

Venn snapshot readiness is owner-scoped and includes its scheduled draw, automatic region-analysis refresh, and species-detection work. Automatic species detection that has not produced visible state is cancelled at the checkpoint boundary rather than being allowed to mutate the payload after cache capture. Restored GO, STRING, and species results establish an input/region baseline: passive hydration, resize, and cache-restoration draws must not rerun those external analyses until the owning tab's actual list or selected-region signature changes. Manual analysis requests remain authoritative, are awaited, and clear their owner tokens on every completion path.

### Owner deactivation and render-cache tiers

Any navigation operation that preserves the outgoing tab—ordinary activation, Add tab, or Duplicate tab—must persist payload/layout and capture its completed owner-scoped render cache before unmounting. These flows share one helper; no tab-creation path may bypass this boundary.

`tab.renderCache` is the bounded warm runtime cache used for immediate tab switching. `tab.archiveRenderCache` is the serialized, owner-scoped checkpoint of the latest completed render for the same payload/layout signatures. Successful capture updates both tiers before warm-cache pruning. Payload or render-affecting layout changes invalidate both tiers. Pruning may clear only the warm runtime tier; it must never erase an otherwise valid archive-ready checkpoint. Archive eligibility requires exact embedded owner and component provenance in addition to payload/layout signature parity; invalid checkpoint objects are discarded during restore staging.

`Shared.renderCacheDiagnostics` records bounded, owner-scoped diagnostic events for cache capture, archive provenance, runtime rehoming, eligibility, component validation, hydration, visual validation, and fallback redraw. It is observational only and never participates in cache eligibility or state authority.

### Restore

1. `Main.sessionActions.restoreDocumentArchive()` parses every `.graph` source through `Shared.graphArchive.parseFile()`.
2. `Main.sessionActions.applyParsedSession()` passes the parsed session to `Main.session.applySessionData()`.
3. `Main.session.applySessionData()` stages new, non-colliding tab owners while the current document remains recoverable.
4. Only the archive's saved active tab is activated and hydrated. Inactive tabs remain canonical payload/session records and hydrate lazily on first selection.
5. The staged document commits only after active-workspace readiness. Activation failure restores the previous tabs and file metadata.
6. Cache restoration requires exact owner, payload-signature, and layout-signature parity. A rejected or absent cache falls back to the component's normal live draw. Restore completion validates the primary graph publication contract rather than scanning the entire workspace root for unrelated SVG/canvas content.
7. A clean restored tab with an exact completed checkpoint keeps its canonical layout when deactivated or inspected. Lifecycle persistence must not recapture the DOM projection merely because another tab is selected. After crash recovery, the consumed recovery archive is treated as the current checkpoint for the newly marked dirty revision; recovery does not immediately serialize the just-restored projection again.
8. The caller then applies the only legitimate source-specific state: a normal file open may retain a file handle and is clean; crash recovery clears any trusted destination and marks the restored document dirty.

`Shared.hot` exclusion mutations are owner-scoped payload transactions. Cell, row, and column exclusions immediately update only the owning tab's canonical `payload.exclusions`, invalidate that tab's caches, increment the session revision, and schedule recovery. Archive/recovery hydration applies exclusions silently.

Detailed schema references are in [docs/development/state-persistence-schema.md](./docs/development/state-persistence-schema.md).

## 6. Directory Responsibilities

- `js/shared/`: reusable infrastructure and cross-component helpers
- `js/components/`: per-graph UI + rendering + component payload
- `js/main/`: workspace/tab/session orchestration
- `css/style.css`: layout + visual styling (source of truth)
- `__tests__/`: Jest unit/integration coverage
- `e2e/`: Playwright browser workflows
- `scripts/`: benchmarks, diagnostics, and now architecture map generator

### CSS loading, ownership, and cascade

`index.html` loads the canonical `css/style.css` before the AG Grid core and Balham theme stylesheets. The AG Grid sheets are preloaded and promoted to stylesheets on load; the `noscript` fallback keeps the same order. A shared rule that competes with AG Grid must therefore be checked against the vendor declaration and its specificity, not judged only by its position inside `style.css`. Preserve this order unless a tested vendor-loading change explicitly replaces it.

The current source order groups presentation by owner: root tokens and base rules; AG Grid geometry and interaction overrides; workspace shell and panel layout; shared controls and toolbar; component-specific graph rules; then cross-component layout, theme, keyboard-focus, and forced-color rules. Responsive conditions mostly sit beside the workspace or component they affect; reduced-motion and forced-color preferences are explicit conditional branches. The HTML and web manifest declare the light application scheme, with no OS-dark stylesheet branch. `style.css` remains the single authored stylesheet; do not split it as a cleanup shortcut.

Root UI tokens define the shared font sizes and regular, medium, semibold, and bold interface weights alongside spacing, the 24px `--ui-target-size-minimum`, the 26px `--ui-menu-item-min-height`, the 220px `--ui-menu-max-height`, border, radius, and overlay values. The 5px `--ui-gap-small` token serves six compact interface gaps. Exact default gray side borders also use `--ui-border-default`; component-specific AG Grid edge colors remain variable-driven. Keep scientific figure styling as a separate domain when its typography or geometry has a different purpose.

Shared AG Grid sizing keeps body-row height and header-row height as separate CSS values. `Shared.hot` reads both values so compact 20px data rows do not reduce the header actions below their 24px target.

Shared AG Grid selection borders, clipboard borders and fill handles are transient projections owned by the table instance. Each native row-content pane hosts a clipped decoration layer, so decorations inherit the exact native scrolling or transforms of that pane. Mixed pinned/body selections expose only the range's outer edges. Pinned rows keep a transparent clipping overhang for the corner handle without changing row spacing; the opaque background and divider stop at the actual row boundary, and input outside rows passes through to the body. Native horizontal scrolling and its scrollbar gutter remain intact. A table-owned mutation observer projects newly virtualized cells, row reuse and cell geometry changes before painting; scroll callbacks do not reposition selection decorations. Destroy disconnects that observer, cancels pending selection/layout frames and removes its layers. Keep these DOM projections out of sessions, payloads and archives; the existing table selection state remains authoritative.

Formula-reference outlines are another transient table projection. They keep per-reference colors with square corners and the same device-pixel-snapped stroke width as the live cell selection border. Each outline is rendered in the shared clipped selection layer inside the same native row-content pane as its cell, so scrolling carries both together without scroll callbacks or later-frame repositioning; the table mutation observer only projects outlines onto recycled or newly virtualized cells.

Runtime inline styles are projections for values that need live geometry or state. `Shared.componentLayout`, `resizer`, `graphSizing`, and `chartStyle` write graph dimensions and measured CSS properties; component/shared builders project conditional visibility; menu and toolbar owners position popups against their triggers; renderers write SVG geometry and data-driven appearance. `Shared.focusModality` records document-wide pointer-versus-keyboard input for focus-ring presentation; it is transient UI state and does not belong to a tab session. Global overlay layers are semantic CSS tokens; `Shared.toolbarOverflow` reads the floating-overlay token when it has no explicit z-index override. Static presentation belongs in CSS, and durable layout state remains in the owning tab session. The static HTML currently has no `style` attributes. The historical owner-category inventory covered 336 `!important` declarations; the CSS now has 48 reviewed priorities across 11 named owners; each allowlist entry records its owner, reason, and registered browser-contract evidence links in `scripts/css-priority-allowlist.json`. At that historical audit point, a PostCSS AST grouped 153 declarations into 106 AG Grid/HOT, 19 shared, 14 workspace, and 14 conditional rules (8 forced-colors, 6 reduced-motion). Subsequent verified removals brought the current count to 48. The shared SVG text editor stores its derived text color as a CSS custom property and uses its preview class for transparent rendering; JavaScript no longer duplicates those appearance values as inline styles. The local/CI priority gate checks each declaration’s selector, property, value, nested at-rule context, owner, reason, and registered browser-scenario links; removals pass, while new or duplicate priorities and unmapped evidence fail. ## 7. Orientation Workflow (Fast Path)

For most changes, this sequence is fastest:

1. Identify workspace type (`tab.type`, component file in `js/components`) or run `npm run dev:entrypoint -- --type <component>`.
2. Inspect `Main.components.registry` entry for the type in `js/main/components.js`.
3. Follow payload path (`getPayload` / `loadFromPayload` / `createEmptyPayload`) in that component.
4. If tab/session behavior is involved, trace through `js/main/session.js` and `js/main/tabs.js`.
5. If helper ambiguity exists, check generated [module-call-map](./docs/development/module-call-map.md).
6. For quick test targeting after edits, run `npm run test:suggest`.
